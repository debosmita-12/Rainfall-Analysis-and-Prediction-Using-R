# Rainfall Analysis and Prediction Using R

A beginner-friendly, reproducible data science project that downloads historical daily precipitation for Kolkata, India, explores rainfall patterns, and compares simple forecasting models in R.

## Project goals
- Retrieve daily precipitation data from the Open-Meteo Historical Weather API.
- Clean and validate dates and rainfall values.
- Explore trends, monthly seasonality, distribution, and missing observations.
- Compare a seasonal-naive baseline with an ETS forecast where the data support it.
- Evaluate predictions on a chronological holdout period using MAE and RMSE.

> **Important:** This is an educational analysis, not an official weather forecast or warning system. The API's historical data coverage and reanalysis/product details can vary. Record the data retrieval date and cite the source in any submission.

## Data source
Open-Meteo Historical Weather API (Archive API): https://open-meteo.com/en/docs/historical-weather-api  
Default location: Kolkata, India (latitude 22.5726, longitude 88.3639).  
Variable: `precipitation_sum` (daily total, millimetres).  
Default period: 2016-01-01 to 2025-12-31. You can change these settings in `R/01_download_data.R`.

## Requirements
- R (4.2 or newer recommended)
- Internet access for the data download
- R packages: `httr2`, `jsonlite`, `dplyr`, `ggplot2`, `lubridate`, `forecast`, `readr`, `tidyr`

## Run the project
Open this folder as your working directory in RStudio, then run these scripts in order:

1. `R/01_download_data.R`
2. `R/02_clean_and_eda.R`
3. `R/03_model_and_evaluate.R`

Each script saves outputs to `data/`, `plots/`, or `results/`. The final results are generated from the data you download; no performance results are fabricated in this repository.

### Install packages
Run in the R console:
```r
install.packages(c("httr2", "jsonlite", "dplyr", "ggplot2", "lubridate",
                   "forecast", "readr", "tidyr"))
```

## Repository structure
```text

  03_model_and_evaluate.R  # Chronological holdout and model comparison

  processed/               # Cleaned data generated by script
plots/                     # EDA and forecast charts
results/                   # Metrics and summaries
report/                    # Final report template
```

## Reproducibility and limitations
- The source file is preserved separately from processed data.
- The test set is the final 20% of the time series; it is not randomly shuffled.
- Forecasting performance depends on data coverage, location, and selected period.
- Rainfall can be zero-heavy and highly seasonal; MAE and RMSE are reported, and MAPE is avoided because it can be undefined at zero.
- Do not claim a model is accurate without running the scripts and reviewing the generated metrics.
- Check the data source's current terms and cite the exact endpoint and retrieval date in your report.
